# Calorie Tracker Journal — деплой на GitHub

Это статическая версия журнала задач (`index.html` + `tasks.json`), которая не зависит
от Claude и может жить вечно на GitHub Pages, Cloudflare Pages, Netlify или Vercel.
Хранилищем данных и системой доступа выступает сам GitHub-репозиторий.

Страница поддерживает **несколько журналов** сразу: при открытии видно главное меню со
списком уже созданных проєктов, кнопка «+ Новий журнал» позволяет создать ещё один и
вписать для него название проєкта и исполнителей (имя + цветовой тег на выбор), у каждого
журнала — свой набор людей и свои задачи по будням.

- **Права на запись** = вы добавляете человека в репозиторий как collaborator, он создаёт
  свой личный токен и "входит" на странице.
- **Права на просмотр** = просто ссылка на опубликованный сайт. Регистрация не нужна.

## 1. Создать репозиторий

1. На github.com → New repository → например `calorie-tracker-journal`.
2. Публичный или приватный — не важно: сама страница после публикации всё равно будет
   открываться по прямой ссылке без входа (так работает GitHub Pages). Приватный репозиторий
   просто прячет исходники от посторонних глаз в поиске.
3. Загрузите туда `index.html` и `tasks.json` из этой папки (через "Add file → Upload files"
   в браузере, либо `git push`, если пользуетесь git).

## 2. Прописать репозиторий в index.html

В начале `<script>` в `index.html` есть блок:

```js
const CONFIG = {
  owner: 'YOUR-GITHUB-USERNAME',
  repo:  'calorie-tracker-journal',
  branch: 'main',
  dataPath: 'tasks.json'
};
```

Замените `owner` на ваш логин/организацию на GitHub, `repo` — на имя репозитория. Сохраните
и закоммитьте изменение.

## 3. Включить GitHub Pages

Settings репозитория → Pages → Source: "Deploy from a branch" → ветка `main`, папка `/ (root)`
→ Save. Через минуту GitHub выдаст ссылку вида
`https://ВАШ-ЛОГИН.github.io/calorie-tracker-journal/` — это и есть постоянный адрес журнала,
он никуда не пропадёт, пока жив репозиторий.

## 4. Дать команде доступ на редактирование

Settings репозитория → Collaborators → Add people → добавьте всех, кто должен вести журналы,
по их GitHub-логинам (права "Write" достаточно). Сам список исполнителей (имена + цвета)
задаётся не здесь, а прямо в интерфейсе при создании каждого журнала.

Дальше каждый из них у себя:

1. Заходит на `github.com/settings/personal-access-tokens/new`.
2. Создаёт **fine-grained token**, ограниченный только этим одним репозиторием
   (Repository access → Only select repositories → `calorie-tracker-journal`).
3. В Permissions выставляет **Contents: Read and write**, остальное не трогает.
4. Копирует токен и на странице журнала жмёт "🔑 Увійти як редактор" → вставляет токен.

Токен хранится только в браузере этого человека (localStorage) и даёт доступ ровно к одному
репозиторию — если он утечёт, ничего кроме этого to-do списка не пострадает, и токен всегда
можно отозвать одним кликом на github.com.

## 5. Заказчик (owner)

Просто отправьте ему ссылку `https://ВАШ-ЛОГИН.github.io/calorie-tracker-journal/`. Он видит
главное меню со списком журналов, открывает нужный и видит доску с прогрессом, но без токена
ни добавить, ни отметить задачу, ни создать/удалить журнал не может — все кнопки редактирования
скрыты, он в режиме просмотра.

Если заказчику нужен доступ только к одному конкретному проєкту (а не ко всему меню со всеми
журналами сразу), можно дать ему прямую ссылку на журнал — она открывает сразу его борд, минуя
меню: `https://ВАШ-ЛОГИН.github.io/calorie-tracker-journal/#j/ID_ЖУРНАЛУ` (ID журнала видно
в адресной строке, когда вы сами открываете этот журнал). Через «← Головне меню» он всё равно
сможет перейти в общий список — если это нежелательно, заводите для разных заказчиков отдельные
репозитории/деплои.

## Важный нюанс

Когда кто-то из команды отмечает задачу, страница отправляет изменение прямо в GitHub (это
настоящий commit в `tasks.json`), но GitHub Pages пересобирает сайт из репозитория не мгновенно —
обычно 20–60 секунд. У того, кто редактировал, всё обновляется сразу на экране, а вот у остальных
просмотр обновится с этой небольшой задержкой (можно нажать "⟳ Оновити", чтобы проверить). Для
дневного планирования задач это не критично.

## Альтернативные хостинги

Файлы `index.html` и `tasks.json` — обычный статический сайт, GitHub тут нужен только как
"база данных + система прав". Поэтому вместо GitHub Pages те же файлы можно задеплоить на:

- **Cloudflare Pages** — pages.cloudflare.com → Create project → Connect to Git → выбрать этот
  репозиторий → Deploy (сборка не нужна, framework preset "None"). Получите адрес вида
  `calorie-tracker-journal.pages.dev`.
- **Netlify** — app.netlify.com → Add new site → Import from Git → тот же репозиторий.
- **Vercel** — vercel.com → New Project → тот же репозиторий.

Во всех трёх случаях данные и права по-прежнему живут в GitHub-репозитории (запись идёт через
GitHub API), меняется только то, где физически открывается сама страница.
